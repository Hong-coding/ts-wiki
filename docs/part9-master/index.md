# Part 9. 마스터 과정

여기까지 왔다면 TypeScript 문법은 거의 다 배웠습니다. 변수와 함수에서 출발해 제네릭, 조건부 타입, 도구 설정, React 실무, 실습 프로젝트 4개까지 끝냈습니다. 마지막 파트는 새 문법을 더 배우는 곳이 아닙니다. **배운 것을 "혼자서도 막힘없이 쓰는 힘"으로 바꾸는 곳**입니다.

## 이 파트가 왜 필요한가요?

문법을 아는 것과 실무에서 TypeScript를 잘 쓰는 것 사이에는 꽤 큰 간격이 있습니다. 실무에서 실제로 시간을 잡아먹는 것은 이런 일들입니다.

- **처음 보는 에러 메시지**가 떴는데 무슨 뜻인지, 어디부터 고쳐야 할지 모르겠습니다.
- 동료의 코드를 리뷰하는데 "동작은 하지만 뭔가 위험해 보이는" 코드를 **말로 설명하지 못합니다**.
- 프로젝트가 커지자 `tsc` 한 번에 몇 분이 걸리고, 에디터 자동 완성이 느려집니다.
- 내가 어디까지 아는지, **무엇을 다시 공부해야 하는지** 객관적으로 알기 어렵습니다.
- 면접에서 "`any`와 `unknown`의 차이를 설명해 보세요" 같은 질문을 받으면, 머릿속으로는 아는데 말로 정리되지 않습니다.

Part 9는 이 다섯 가지 문제를 하나씩 다룹니다. 사전처럼 찾아보는 에러 모음, 리뷰 체크리스트, 성능 진단 방법, 자가 진단 시험, 면접 질문 모음, 그리고 이 위키를 떠난 뒤에도 계속 성장하는 방법까지 담았습니다.

## 학습 흐름

| 순서 | 레슨 | 무엇을 하나요 |
|---|---|---|
| 1 | 자주 만나는 컴파일 에러 사전 | TS2322, TS2345 같은 에러 코드 30여 개를 "원문 → 뜻 → 재현 → 원인 → 해결" 순으로 정리합니다. |
| 2 | 안티패턴과 코드 리뷰 체크리스트 | `any`·`as`·`!` 남발처럼 동작은 하지만 위험한 코드 15가지를 고치고, 리뷰할 때 볼 항목을 정리합니다. |
| 3 | 대규모 코드베이스 | `skipLibCheck`, `incremental`, 프로젝트 참조로 큰 프로젝트의 타입 검사를 빠르게 만듭니다. |
| 4 | 단계별 자가 진단 테스트 | Part 0~8을 파트별 문제로 점검하고, 점수에 따라 복습할 레슨을 찾습니다. |
| 5 | 면접·실무 질문 50선 | 자주 나오는 질문 50개와 모범 답변의 요지를 주제별로 정리합니다. |
| 6 | 다음 단계와 추천 학습 자료 | 공식 문서·릴리스 노트·연습 사이트 등 믿을 만한 자료와 계속 성장하는 방법을 소개합니다. |

::: tip 순서대로 읽지 않아도 됩니다
1번(에러 사전)과 2번(안티패턴)은 **찾아보는 문서**입니다. 처음에 한 번 훑어보고, 실무에서 에러를 만나거나 코드 리뷰를 할 때 다시 펼쳐 보세요. 실력을 먼저 확인하고 싶다면 4번(자가 진단)부터 풀어도 좋습니다.
:::

## 이 파트를 마치면

- 처음 보는 TypeScript 에러도 **에러 코드와 메시지 구조**로 원인을 좁혀 스스로 고칠 수 있습니다.
- 남의 코드에서 `any`·`as`·`!` 남발, 타입과 런타임의 불일치 같은 위험 신호를 찾아 **근거를 들어 리뷰**할 수 있습니다.
- 느린 타입 검사를 `--extendedDiagnostics`, `--generateTrace`로 진단하고, 프로젝트 참조로 큰 저장소를 나눌 수 있습니다.
- 내 실력의 빈 곳을 객관적으로 찾아 복습 계획을 세울 수 있습니다.
- TypeScript의 핵심 개념을 면접관이나 동료에게 **짧고 정확하게 말로 설명**할 수 있습니다.
- 새 TypeScript 버전이 나왔을 때 무엇이 바뀌었는지 스스로 찾아 읽을 수 있습니다.

## 막히면 이렇게 하세요

1. **링크된 레슨으로 돌아갑니다.** 이 파트의 거의 모든 항목에 관련 레슨 링크가 붙어 있습니다. 설명이 어렵게 느껴지면 그 개념을 처음 배운 레슨을 다시 읽는 것이 가장 빠릅니다.
2. **에러 코드로 찾습니다.** 에러 메시지 끝의 `TS2322` 같은 번호는 버전이 바뀌어도 거의 그대로입니다. 에러 사전 맨 위의 빠른 찾기 표에서 번호로 찾아보세요.
3. **작게 줄여서 재현합니다.** 큰 파일에서 나는 에러는 관련 없는 코드를 지워 10줄 안팎으로 줄여 보세요. 줄이는 과정에서 원인이 보이는 경우가 많습니다. [TS Playground](../part0-start/04-playground)가 이럴 때 가장 편합니다.
4. **자가 진단 점수가 낮아도 괜찮습니다.** 점수는 "어디를 다시 보면 되는지" 알려 주는 지도일 뿐입니다. 안내된 레슨을 복습한 뒤 다시 풀어 보세요.

::: info 마스터는 끝이 아니라 습관입니다
TypeScript는 1년에 몇 차례 새 버전이 나옵니다. 이 파트의 목표는 "모든 것을 외운 상태"가 아니라 "모르는 것을 만났을 때 스스로 찾아서 해결하는 습관"을 갖는 것입니다.
:::
