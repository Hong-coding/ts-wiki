# Part 4. 비동기 프로그래밍과 데이터 다루기

Part 3까지 쓴 코드는 모두 "지금 이 자리에서" 값을 계산하고 끝났습니다. 상품 배열을 거르고, 주문 금액을 더하고, 타입을 파생해 붙였습니다. 필요한 값은 이미 코드 안이나 메모리 안에 있었습니다.

그런데 실제 프로그램이 다루는 값은 대부분 **바깥에서, 나중에** 들어옵니다.

- POS 화면이 상품 목록을 보여 주려면 서버에 물어보고 **응답이 올 때까지** 기다려야 합니다.
- 카드 결제는 카드사 승인이 떨어질 때까지 몇 초가 걸립니다. 그 사이에 화면이 굳으면 안 됩니다.
- 서버가 보내 준 JSON이 정말 우리가 약속한 모양인지, 날짜 문자열이 한국 시간인지 UTC인지 누구도 보장해 주지 않습니다.

이 두 가지, 곧 **"시간"** 과 **"바깥에서 온 데이터"** 를 다루는 것이 Part 4의 주제입니다.

## 왜 비동기가 필요한가

자바스크립트는 일을 처리하는 일꾼(실행 스레드, thread)이 **하나뿐**입니다. 직원 한 명이 운영하는 식당과 같습니다. 이 직원이 음식이 나올 때까지 계산대 앞에 서서 기다린다면, 뒤에 선 손님은 아무것도 못 하고 줄만 섭니다. 브라우저라면 화면이 멈추고 버튼이 눌리지 않습니다.

그래서 오래 걸리는 일(네트워크 요청, 타이머, 파일 읽기)은 주방에 맡겨 두고 손님에게 **진동벨**을 줍니다. 직원은 곧바로 다음 손님을 받고, 벨이 울리면 그때 음식을 건넵니다. 이것이 **비동기(asynchronous)** 방식입니다.

```ts
// 지금은 문법을 몰라도 괜찮습니다. 모양만 보세요.
async function showProducts(): Promise<void> {
  const res = await fetch('https://example.com/api/products') // 서버 응답을 기다림(화면은 멈추지 않음)
  const products: unknown = await res.json()                  // 무엇이 왔는지 아직 모름
  console.log(products)
}
```

이 짧은 코드에 Part 4에서 배울 내용이 거의 다 들어 있습니다. `async`/`await`, `Promise<void>`, `fetch`, 그리고 "응답을 `unknown`으로 받는 이유"까지 모두 하나씩 풀어 갑니다.

## 타입이 "사라지는" 문제

Part 4의 후반부는 또 다른 문제를 다룹니다. TypeScript의 타입은 **컴파일할 때만** 존재하고, 실행되는 JavaScript에는 남지 않습니다. 그래서 서버가 `price`를 숫자 대신 문자열 `"4500"`으로 보내도, 코드에 `price: number`라고 적어 둔 것만으로는 막을 수 없습니다.

```ts
interface Product {
  name: string
  price: number
}

// 컴파일러는 "개발자가 Product라고 했으니 믿겠다"고 넘어갑니다.
const product = JSON.parse('{"name":"아메리카노","price":"4500"}') as Product
console.log(product.price + 500) // 출력: 4500500  ← 덧셈이 아니라 문자열 이어 붙이기!
```

이런 사고를 막으려면 **실행 중에 값을 직접 검사**해야 합니다(런타임 검증). Part 4에서는 검증 함수를 손으로 짜 보고, 실무에서 많이 쓰는 라이브러리 zod로 같은 일을 짧게 하는 법을 배웁니다.

## 이 파트를 마치면

- `setTimeout`, `then`, `await`가 섞인 코드의 실행 순서를 이벤트 루프 규칙으로 설명할 수 있습니다.
- Promise를 직접 만들고, 여러 비동기 작업을 순서대로 또는 동시에 실행할 수 있습니다(`Promise.all` 등).
- `async`/`await`와 `try/catch`로 읽기 쉬운 비동기 코드를 쓰고, 오류가 조용히 사라지지 않게 처리할 수 있습니다.
- `fetch`로 REST API를 호출하고, 응답에 타입을 붙이는 공통 함수 `request<T>()`를 만들 수 있습니다. 타임아웃과 취소도 처리합니다.
- 서버 응답·폼 입력처럼 믿을 수 없는 데이터를 zod로 검증하고, 스키마에서 타입을 자동으로 뽑아낼 수 있습니다.
- JSON·Date·Map·Set을 쓸 때 생기는 타입 함정(`any`, 타임존, 직렬화)을 피할 수 있습니다.

:::

::: tip 마우스를 올려 타입을 확인하세요
`async` 함수의 반환 타입, `await`한 값의 타입, `res.json()`의 타입처럼 Part 4에는 "눈에 보이지 않는 타입"이 많습니다. VS Code나 [TS Playground](../part0-start/04-playground)에서 변수 위에 마우스를 올려 TypeScript가 계산한 타입을 꼭 확인하세요. `Promise<number>`여야 할 곳에 다른 타입이 보이면 어딘가에서 `await`를 빠뜨렸다는 신호인 경우가 많습니다.
:::
