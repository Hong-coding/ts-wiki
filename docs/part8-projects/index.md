# Part 8. 실습 프로젝트

지금까지 문법과 타입 기법을 하나씩 배웠습니다. 하지만 "레슨의 예제를 이해하는 것"과 "빈 폴더에서 동작하는 프로그램을 끝까지 만드는 것"은 전혀 다른 능력입니다. 이 파트에서는 배운 내용을 묶어 **혼자 힘으로 동작하는 프로그램 4개**를 완성합니다.

## 왜 프로젝트인가

- **기억이 연결됩니다.** 판별 유니온, 타입 가드, 제네릭을 따로 배울 때는 "이걸 언제 쓰지?"라는 의문이 남습니다. 프로젝트에서는 "사용자 입력이 잘못됐을 때", "서버 응답이 없을 때"처럼 **필요한 순간**에 꺼내 쓰게 됩니다.
- **설계를 연습합니다.** 코드를 쓰기 전에 "데이터가 어떤 모양인가"를 타입으로 먼저 정하는 습관은 프로젝트를 해 봐야 몸에 붙습니다.
- **실무 흐름을 미리 겪습니다.** 패키지 설치, `tsconfig.json` 설정, 개발 서버, 테스트, 빌드까지 실제 개발과 같은 순서로 진행합니다.

## 네 프로젝트의 흐름

| 프로젝트 | 만드는 것 | 새로 다루는 것 | 이어지는 것 |
|---|---|---|---|
| 1. 콘솔 가계부 | 터미널 가계부 | Node.js 파일 입출력, readline, 입력 검증 | 판별 유니온 명령 처리 |
| 2. Todo 웹앱 | 브라우저 할 일 목록 | DOM 타입과 `null` 처리, 이벤트 위임, localStorage | 상태 → 렌더 단방향 |
| 3. 주문 REST API | 카페 주문 서버 | Express, zod 요청 검증, 저장소 인터페이스, Vitest | 상태 전이 판별 유니온, 공통 에러 |
| 4. React 주문 앱 | 카페 주문 화면 | React, zustand, Vite 프록시 | 프로젝트 3 API를 그대로 사용 |

뒤로 갈수록 규모가 커지지만 뼈대는 같습니다. **타입을 먼저 설계하고 → 순수한 계산 로직을 만들고 → 마지막에 입출력(화면·파일·HTTP)을 붙입니다.** 프로젝트 3과 4는 하나의 서비스(서버 + 화면)이므로 순서대로 진행하세요.

## 진행 방법

각 프로젝트 레슨은 같은 순서로 되어 있습니다. 이 순서대로 진행해야 실력이 늡니다.

1. **요구사항 읽기**: "완성하면 이렇게 됩니다"와 "요구사항"을 읽고, 무엇을 만들지 머릿속에 그립니다.
2. **스스로 설계하기**: "설계하기"의 팁 상자에 있는 질문에 답하며, 빈 파일에 타입부터 직접 적어 봅니다. 10~20분이면 충분합니다. 틀려도 괜찮습니다.
3. **단계별 가이드 따라가기**: 자신의 설계와 레슨의 설계를 비교한 뒤, Step 1부터 만듭니다. 각 Step의 "실행 확인"과 "체크포인트"를 통과한 뒤 다음으로 넘어갑니다. 코드를 복사하기보다 **직접 타이핑**하는 편이 훨씬 많이 남습니다.
4. **완성 코드와 비교하기**: 다 만들었으면 위키 저장소의 `examples/projects/` 폴더에 있는 완성 코드와 비교합니다. 다르게 만든 부분이 꼭 틀린 것은 아닙니다. "왜 이렇게 했을까?"를 생각해 보세요.
5. **도전 과제와 회고**: 도전 과제 중 하나 이상을 해 보고, 회고 질문에 글로 답합니다.

::: tip 준비물
- Node.js 22.12 이상(Vite 8의 요구 사항, 작성 시점 확인 버전: 24.13.1)과 VS Code. 설치는 [개발 환경 설치](../part0-start/03-setup)를 보세요.
- 완성 코드의 각 폴더에서 `npm install`을 먼저 실행합니다. 프로젝트마다 사용한 패키지 버전은 각 레슨의 Step 1에 적어 두었습니다.
- 개발 서버(`npm run dev`)는 끝낼 때 터미널에서 `Ctrl+C`로 꼭 종료하세요. 켜 둔 채로 다른 프로젝트를 띄우면 포트 충돌(`EADDRINUSE`)이 날 수 있습니다.
:::

## 막혔을 때

먼저 **에러 메시지를 끝까지 읽습니다**([에러 메시지 읽는 법](../part0-start/06-how-to-read-errors)). 에러 코드(TS2322 등)가 있으면 [컴파일 에러 사전](../part9-master/01-error-dictionary)에서 찾아봅니다. 그래도 막히면 아래 표에서 관련 레슨으로 돌아갑니다.

|---|---|

::: warning any와 as로 에러를 지우지 마세요
막혔을 때 가장 쉬운 탈출구는 `any`나 `as`로 에러를 없애는 것입니다. 그러면 컴파일은 되지만 실행 중에 더 찾기 어려운 버그로 돌아옵니다. 이 파트의 완성 코드에는 `any` 표기가 하나도 없고, `as`는 꼭 필요한 곳에만 이유와 함께 썼습니다. 에러가 나면 "컴파일러가 무엇을 걱정하는가?"를 먼저 생각해 보세요.
:::

## 마치면 할 수 있는 것

- 요구사항을 읽고 타입부터 설계해 작은 프로그램을 처음부터 끝까지 만들 수 있다.
- 바깥에서 들어오는 값(키보드 입력, 파일, localStorage, HTTP 요청·응답)을 검사하고, 안쪽 코드는 타입을 믿고 쓸 수 있다.
- 콘솔 프로그램, 웹 화면, API 서버, React 앱의 기본 구조를 TypeScript로 잡을 수 있다.
- 테스트로 요구사항을 확인하고, 빌드까지 마칠 수 있다.
