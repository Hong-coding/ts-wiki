# Part 3. 타입 시스템 중급

Part 2에서는 값 하나하나에 알맞은 타입을 붙이는 법을 배웠습니다. `string`, `number`, 객체 타입, 유니온, 인터페이스, 타입 좁히기까지 익혔다면 웬만한 코드에는 타입을 붙일 수 있습니다.

그런데 실무 코드를 조금만 써 보면 이런 장면을 자주 만납니다.

- 상품 등록 화면, 상품 수정 화면, 상품 목록 화면이 모두 "상품"을 다루는데, 화면마다 필요한 속성이 조금씩 다릅니다. 그래서 `Product`, `ProductForUpdate`, `ProductListItem`을 따로 만들었더니, 상품에 속성 하나가 추가될 때마다 세 곳을 모두 고쳐야 합니다.
- 배열에서 첫 번째 값을 꺼내는 함수를 만들었는데, 상품 배열용·주문 배열용·회원 배열용을 따로 만들거나 `any`로 타입을 포기하게 됩니다.
- 결제 수단이 카드·현금·포인트로 나뉘는데, 새 결제 수단이 추가되었을 때 처리를 빠뜨린 곳을 컴파일러가 알려 주면 좋겠습니다.

이 문제들의 공통점은 **같은 타입 정보를 여러 번 손으로 적고 있다**는 것입니다. 손으로 여러 번 적은 정보는 언젠가 서로 어긋납니다. Part 3의 목표는 타입을 한 번만 정의하고, 나머지는 그 타입에서 **만들어 내는(파생하는)** 방법을 익히는 것입니다. 이렇게 한 번 정의해 여러 곳에서 다시 쓰는 타입을 이 위키에서는 "재사용 가능한 타입"이라고 부릅니다.

## 왜 "재사용 가능한 타입"이 필요한가

상품 타입을 예로 들어 보겠습니다. 손으로 따로따로 적으면 이렇게 됩니다.

```ts
// 상품 전체 정보
interface Product {
  id: number
  name: string
  price: number
  stock: number
}

// 수정 API에 보내는 값: 모든 속성이 있어도 되고 없어도 됨
interface ProductUpdate {
  name?: string
  price?: number
  stock?: number
}

// 목록 화면에 보여 줄 값: 일부 속성만
interface ProductListItem {
  id: number
  name: string
  price: number
}
```

`Product`에 `category`를 추가하면 다른 두 타입은 아무도 알려 주지 않은 채 낡은 상태로 남습니다. Part 3을 마치면 같은 내용을 이렇게 쓸 수 있습니다.

```ts
interface Product {
  id: number
  name: string
  price: number
  stock: number
}

// Product에서 파생: Product가 바뀌면 자동으로 따라 바뀝니다.
type ProductUpdate = Partial<Omit<Product, 'id'>>
type ProductListItem = Pick<Product, 'id' | 'name' | 'price'>
```

지금은 `Partial`, `Omit`, `Pick`이 무엇인지 몰라도 괜찮습니다. 3-7 레슨에서 하나씩 배웁니다. 핵심은 **진짜 정보는 한 곳(`Product`)에만 있고, 나머지는 거기서 계산된다**는 점입니다.

## 이 파트를 마치면

- 여러 타입을 조합해 새 타입을 만들고(인터섹션), 상태마다 모양이 다른 데이터를 안전하게 다룰 수 있습니다(판별 유니온).
- TypeScript가 "이 값을 저 변수에 넣어도 되는가"를 어떤 규칙으로 판단하는지 설명할 수 있습니다(구조적 타이핑).
- 제네릭으로 "어떤 타입이 와도 동작하되 타입 정보는 잃지 않는" 함수와 타입을 만들 수 있습니다.
- `keyof`, `typeof`, 인덱스 접근 타입, 내장 유틸리티 타입으로 기존 타입에서 새 타입을 뽑아낼 수 있습니다.
- 클래스와 모듈을 타입 안전하게 쓰고, 언제 클래스를 쓰고 언제 쓰지 않을지 판단할 수 있습니다.

Part 3은 네 덩어리로 나뉩니다. 앞 레슨의 내용을 뒤 레슨에서 계속 쓰므로 순서대로 읽기를 권합니다.

| 2. 타입에 매개변수 달기 | 3-4 제네릭 기초, 3-5 제네릭 제약 | 타입도 함수처럼 "입력"을 받게 만들 수 있는가? |
