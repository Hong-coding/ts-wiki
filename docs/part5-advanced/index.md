# Part 5. 고급 타입

지금까지 우리는 **값**을 다루는 프로그램을 짰습니다. 변수에 숫자를 넣고, 조건문으로 갈림길을 만들고, 반복문으로 같은 일을 여러 번 했습니다. 그리고 그 값에 알맞은 **타입**을 붙이는 법을 배웠습니다.

Part 5에서는 발상을 한 번 뒤집습니다. **타입 자체를 재료로 삼아, 타입으로 프로그래밍합니다.**

## "타입으로 프로그래밍한다"는 말의 뜻

값 레벨(value level, 프로그램이 실행될 때 실제로 움직이는 숫자·문자열·객체의 세계)에는 조건문·반복문·함수·재귀가 있습니다. TypeScript의 타입 레벨(type level, 컴파일러가 코드를 검사할 때만 존재하는 타입의 세계)에도 이와 거의 똑같은 도구가 있습니다.

| 값 레벨에서 하던 일 | 타입 레벨의 대응 | 배우는 레슨 |
|---|---|---|
| 삼항 연산자 `a ? b : c` | 조건부 타입 `T extends U ? X : Y` | 01 |
| 구조 분해로 값 꺼내기 | `infer`로 타입 꺼내기 | 02 |
| `for` 루프로 객체 속성 하나씩 바꾸기 | 매핑된 타입 `[K in keyof T]` | 03 |
| 템플릿 리터럴로 문자열 만들기 | 템플릿 리터럴 타입 | 04 |
| 자기 자신을 부르는 재귀 함수 | 재귀 타입 | 05 |
| `if`로 값의 종류 확인하기 | 사용자 정의 타입 가드 | 06 |

함수가 "값을 받아 값을 돌려주는 것"이라면, 제네릭 타입은 "타입을 받아 타입을 돌려주는 것"입니다. Part 3에서 배운 제네릭이 바로 타입 레벨의 함수였습니다. 이번 파트에서는 그 함수 안에 조건과 반복과 재귀를 넣는 법을 배웁니다.

```ts
// 값 레벨: 값을 받아 값을 돌려주는 함수
function toLabel(isMember: boolean) {
  return isMember ? '회원' : '비회원'
}
console.log(toLabel(true)) // 출력: 회원

// 타입 레벨: 타입을 받아 타입을 돌려주는 "타입 함수"
type ToLabel<T> = T extends true ? '회원' : '비회원'

type A = ToLabel<true> // 결과: '회원'
type B = ToLabel<false> // 결과: '비회원'
```

두 코드의 모양이 무척 닮았습니다. 이 닮은 점을 붙잡고 따라가는 것이 이 파트의 핵심 학습 방법입니다.

## 이 파트가 실무에서 쓰이는 곳

"이런 걸 실무에서 정말 쓰나?" 하는 의문이 들 수 있습니다. 매일 직접 만들지는 않더라도, **매일 읽게 됩니다.**

- **라이브러리 타입 읽기**: React의 `ComponentProps`, Vue의 `defineProps`, zustand·react-hook-form·zod의 타입은 조건부 타입·`infer`·매핑된 타입으로 만들어져 있습니다. 에러 메시지에 이런 타입이 그대로 찍혀 나오므로, 읽을 줄 알아야 에러를 해결할 수 있습니다.
- **API 응답 타입 변환**: 서버가 주는 주문(`Order`) 타입에서 "수정 폼용 타입"(모든 속성 선택)이나 "목록 화면용 타입"(일부 속성만)을 손으로 다시 쓰지 않고 만들어 냅니다. 원본이 바뀌면 파생 타입도 함께 바뀌므로 실수가 줄어듭니다.
- **이벤트·라우터 타입**: `'order:created'` 같은 이벤트 이름이나 `/stores/:storeId/orders/:orderId` 같은 경로 문자열에서 매개변수 이름을 타입으로 뽑아 냅니다.
- **타입 없는 JS 라이브러리 쓰기**: 사내에 오래된 JS 모듈이 있다면 선언 파일(`.d.ts`)을 작성해 타입을 입힙니다.
- **런타임 검증과 연결**: 사용자 정의 타입 가드와 assertion 함수로 "실행 중 확인"과 "컴파일러의 타입 판단"을 이어 줍니다.

## 어렵게 느껴질 때의 학습 요령

이 파트는 이 위키에서 가장 추상적인 부분입니다. 한 번에 이해되지 않는 것이 정상입니다. 아래 요령이 도움이 됩니다.

::: tip 1. 값 레벨 코드로 먼저 써 보세요
타입이 머릿속에 그려지지 않으면, 같은 일을 하는 JavaScript 함수를 먼저 써 봅니다. 그다음 `if`는 `extends ? :`로, `for`는 `in keyof`로, 함수 호출은 재귀 타입으로 한 줄씩 옮깁니다. 모든 레슨이 이 방식으로 설명되어 있습니다.
:::

::: tip 2. 마우스를 올려 보세요
VS Code나 [TS Playground](../part0-start/04-playground)에서 타입 이름 위에 마우스를 올리면 계산된 결과가 보입니다. 새 타입을 만들 때마다 `type R = ...`를 하나 만들어 결과를 확인하는 습관을 들이세요.
:::

::: tip 3. 작은 입력부터 넣어 보세요
`DeepReadonly`가 어떻게 동작하는지 모르겠다면 `{ a: number }`처럼 아주 작은 타입을 넣어 손으로 한 단계씩 전개해 봅니다. 레슨마다 "전개 과정"을 단계별로 적어 두었으니 종이에 따라 써 보세요.
:::

::: tip 4. 완벽하게 외우려 하지 마세요
실무에서는 직접 만드는 일보다 **읽는** 일이 훨씬 많습니다. 처음에는 "아, 이건 조건부 타입이구나", "이건 키를 바꾸는 매핑된 타입이구나" 하고 알아보는 것만으로 충분합니다. 9번 레슨의 연습 문제로 실력을 천천히 쌓으면 됩니다.
:::

::: tip 5. 막히면 한 레슨 쉬었다 돌아오세요
01·02·03 레슨은 서로 기대고 있습니다. 02에서 막히면 01을 다시 읽고, 03에서 막히면 Part 3의 `keyof` 레슨을 다시 보세요. 두 번째 읽을 때 훨씬 잘 보입니다.
:::

::: warning 너무 영리한 타입은 피하세요
타입 레벨 프로그래밍은 재미있어서 과하게 쓰기 쉽습니다. 동료가 읽을 수 없는 타입, 에러 메시지가 수십 줄씩 나오는 타입은 오히려 해가 됩니다. "이 타입이 실수를 막아 주는가, 읽기 쉬운가"를 늘 함께 따져 보세요.
:::
