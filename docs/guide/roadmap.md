# 학습 로드맵

이 위키는 **프로그래밍을 한 번도 해 보지 않은 사람**이 TypeScript를 실무에서 자신 있게 쓰는 수준까지 가도록 설계했습니다. 순서대로 따라오면 앞에서 배우지 않은 내용이 뒤에서 갑자기 나오지 않습니다.

## 한눈에 보는 전체 흐름

```text
 [입문]            [초급]           [중급]                 [고급]          [실전]                         [마스터]
 Part 0 시작하기 → Part 2 타입 기초 → Part 3 타입 중급    → Part 5 고급 타입 → Part 6 도구·설정              → Part 9 마스터 과정
 Part 1 프로그래밍     │              Part 4 비동기·데이터      │              Part 7 프레임워크·타입 설계
        기초           │                    │                   │              Part 8 실습 프로젝트(4개)
                       └──── 프로젝트 1·2 ──┘                   └──── 프로젝트 3·4
```

| 단계 | 파트 | 이 단계를 마치면 할 수 있는 것 |
|---|---|---|
| 입문 | [Part 0 시작하기](../part0-start/), [Part 1 프로그래밍 기초](../part1-basics/) | 내 PC에서 TS 프로그램을 만들고 실행한다. 변수·조건·반복·함수·배열·객체로 간단한 계산 프로그램을 짠다. |
| 초급 | [Part 2 타입 시스템 기초](../part2-types/) | 코드에 알맞은 타입을 붙이고, 빨간 줄(타입 오류)이 왜 생겼는지 읽고 고친다. |
| 중급 | [Part 3 타입 시스템 중급](../part3-intermediate/), [Part 4 비동기](../part4-async/) | 제네릭·유틸리티 타입으로 재사용 가능한 타입을 만들고, API를 호출해 받은 데이터를 안전하게 다룬다. |
| 고급 | [Part 5 고급 타입](../part5-advanced/) | 라이브러리의 복잡한 타입 정의를 읽고, 조건부·매핑 타입으로 직접 만든다. |
| 실전 | [Part 6 도구](../part6-tooling/), [Part 7 프레임워크](../part7-practice/), [Part 8 프로젝트](../part8-projects/) | 프로젝트를 처음부터 구성하고, React·Vue·Node 실무 코드에서 타입을 설계한다. |
| 마스터 | [Part 9 마스터 과정](../part9-master/) | 낯선 에러를 스스로 해결하고, 남의 코드를 리뷰하며, 실력을 객관적으로 점검한다. |

## 어디서부터 시작할까요?

| 내 상황 | 시작 위치 |
|---|---|
| 코딩이 처음이다 | [Part 0-1](../part0-start/01-what-is-programming)부터 순서대로 |
| 다른 언어(Java, C# 등)는 해 봤지만 JavaScript는 모른다 | [Part 0-3 환경 설치](../part0-start/03-setup) → Part 1은 각 레슨의 "자주 하는 실수"와 연습 문제 위주로 빠르게 → Part 2부터 정독 |
| JavaScript는 쓸 줄 안다 | [Part 1 자가 진단](../part9-master/04-self-assessment)을 풀어 보고 통과하면 [Part 2](../part2-types/)부터 |
| TS를 실무에서 쓰지만 기초가 불안하다 | [자가 진단 테스트](../part9-master/04-self-assessment)로 약한 파트를 찾아 그 파트만 |

## 이 위키를 끝까지 마쳤다는 것의 의미

- 타입 오류 메시지를 보고 원인을 스스로 찾아 고칠 수 있습니다.
- `any` 없이 외부 API 응답, 폼 입력, 상태 관리를 타입 안전하게 다룰 수 있습니다.
- 제네릭·조건부 타입이 섞인 라이브러리 타입 정의를 읽고 이해할 수 있습니다.
- 새 프로젝트의 tsconfig·린터·테스트·빌드를 직접 구성할 수 있습니다.
- 동료의 TS 코드를 리뷰하고 더 나은 타입 설계를 제안할 수 있습니다.
