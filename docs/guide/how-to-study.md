# 이 위키로 공부하는 법

## 레슨 한 개는 이렇게 생겼습니다

모든 레슨은 같은 순서로 되어 있습니다. 순서가 같으면 "지금 어디쯤 읽고 있는지" 헷갈리지 않습니다.

| 순서 | 섹션 | 하는 일 |
|---|---|---|
| 1 | 이번에 배울 것 | 레슨이 끝나면 할 수 있어야 하는 것. **다 읽은 뒤 다시 와서 스스로 체크**합니다. |
| 2 | 먼저 알아 둘 것 | 이 레슨을 이해하는 데 필요한 앞 레슨. 기억이 안 나면 먼저 다시 봅니다. |
| 3 | 비유로 이해하기 | 일상의 예로 개념의 핵심을 먼저 잡습니다. |
| 4 | 개념 설명 | 예제 코드 → 실행 결과 → 해설 순서로 설명합니다. |
| 5 | 자주 하는 실수 | 초보자가 실제로 많이 틀리는 코드와 고친 코드. |
| 6 | 직접 해 보기 | 연습 문제. ⭐ 기초 / ⭐⭐ 응용 / ⭐⭐⭐ 도전 |
| 7 | 확인 퀴즈 | 개념을 정확히 이해했는지 확인하는 짧은 질문. |
| 8 | 정리 | 핵심 요약. 복습할 때는 이 부분만 읽어도 됩니다. |

## 공부 방법 7가지

### 1. 예제는 반드시 직접 타이핑합니다
복사·붙여넣기보다 손으로 쳐 보는 것이 훨씬 오래 기억에 남습니다. 오타가 나서 에러가 생기는 것도 공부입니다.

### 2. 코드를 일부러 망가뜨려 봅니다
예제가 돌아가면 숫자를 문자열로 바꾸거나 속성 이름을 틀리게 써 보세요. 어떤 에러가 나는지 보는 것이 타입 시스템을 이해하는 가장 빠른 길입니다.

### 3. 정답을 보기 전에 최소 15분은 고민합니다
연습 문제의 정답은 접혀 있습니다. 바로 펼치지 말고 먼저 풀어 보세요. 15분을 고민해도 모르겠으면 그때 정답을 보고, **다음 날 정답을 보지 않고 다시 풀어 봅니다.**

### 4. 마우스를 타입 위에 올려 봅니다
VS Code에서 변수나 함수 위에 마우스를 올리면 TypeScript가 생각하는 타입이 보입니다. 내가 예상한 타입과 같은지 확인하는 습관을 들이세요.

### 5. 에러 메시지를 끝까지 읽습니다
에러 메시지는 적이 아니라 힌트입니다. 처음엔 영어라 어렵지만 [에러 메시지 읽는 법](../part0-start/06-how-to-read-errors)과 [에러 사전](../part9-master/01-error-dictionary)을 옆에 두고 읽으면 금방 익숙해집니다.

### 6. 파트가 끝날 때마다 자가 진단을 풉니다
[자가 진단 테스트](../part9-master/04-self-assessment)에는 파트별 문제가 있습니다. 기준 점수에 못 미치면 안내된 레슨을 복습한 뒤 넘어갑니다.

### 7. 공부 기록을 남깁니다
GitHub에 저장소를 하나 만들어 연습 문제 풀이를 올려 두면, 나중에 내가 얼마나 성장했는지 볼 수 있고 Git 사용법도 함께 익힙니다.

## 막혔을 때

1. 에러 메시지 전체를 복사해 [에러 사전](../part9-master/01-error-dictionary)에서 에러 코드(TS2322 같은 번호)를 찾습니다.
2. [TS Playground](../part0-start/04-playground)에 문제가 되는 코드만 최소한으로 옮겨 다시 실행해 봅니다.
3. [용어집](../appendix/01-glossary)에서 모르는 단어를 찾습니다.
4. 그래도 안 되면 다른 사람이나 AI에게 질문합니다. 질문하는 법은 [에러 메시지 읽는 법과 도움 받는 법](../part0-start/06-how-to-read-errors)에 있습니다.

::: warning 회사 코드로 질문할 때
외부 사이트나 AI에 질문할 때는 고객사 이름, 서버 주소, 계정 정보, 실제 고객 데이터가 들어가지 않도록 코드를 최소화하고 이름을 바꿔서 올립니다.
:::
